# Loginflare

基于 Cloudflare 的开源账号与身份管理系统。

[English](README.md) · [部署说明](docs/deployment.zh-CN.md) · [应用接入](docs/oauth.zh-CN.md) · [架构说明](docs/architecture.md) · [规模与验证](docs/scaling.md)

Loginflare 是完整可用的通用账号与身份管理平台，面向从小团队到大型公开服务的独立部署。它包含面向用户的账号中心、开发者中心、管理控制台，以及供独立 Web 和 SPA 应用接入的标准 OAuth/OIDC 登录能力，支持邮箱或用户名登录、邮箱验证、密码恢复和会话管理。系统通过一个 Cloudflare Worker 运行，使用 D1、R2、Email Service、Turnstile 和 Workers Static Assets。

维护者当前运行供本人功能验收的测试实例，这不限制独立部署的实际用途。该实例的管理后台仅限管理员访问。其他使用者通过 fork 代码、自行配置资源并独立部署来使用 Loginflare。Web/SPA 示例用于验证完整的应用接入流程；面向具体业务的应用可在独立分支中开发，加入各自的品牌和业务规则。

产品默认语言为 **`en-US`**，可手动选择 **`zh-CN`**。页面网址使用小写语言段：`/en-us/`、`/zh-cn/`。

## 功能

- 注册、验证邮箱、重发验证邮件，使用邮箱或用户名登录，以及退出。
- 管理 Google、GitHub、Microsoft、Discord、X、Telegram、OIDC 和 OAuth 2.0 连接器，支持无密码注册、显式绑定与第三方再次认证，详见[第三方登录](docs/social.zh-CN.md)。
- 找回密码，以及通过当前密码修改密码。
- 验证器动态码（TOTP）MFA，支持一次性恢复码的保存与重置，覆盖邮箱、用户名及 OAuth 登录。
- 修改显示名称与用户名、上传和裁剪头像、查看和撤销活跃会话。
- 在独立页面管理主邮箱与辅助邮箱，通过验证码验证新地址并切换主邮箱。
- 按完整 ID、用户名或主邮箱精确查找与查看用户、停用与恢复普通账号、撤销用户会话。
- 开发者自行创建和管理服务端 Web 与 SPA 客户端，配置精确回调地址、用户同意与客户端密钥轮换；管理员管理全部应用。
- 管理员设置整站 Logo、品牌名、主题色与 Material 配色方案。
- 通过授权码 + PKCE S256 登录，提供 OIDC 发现、UserInfo、RS256 ID Token、刷新令牌和应用发起的中心退出。
- 英文和简体中文页面、错误提示与事务邮件。
- 复用 Better Auth 的账号与会话能力，使用 D1 原子持久化限流和定时过期数据清理，服务端验证 Turnstile。

当前版本不包含组织、多租户、SAML、删除账号、网页分配角色、模拟登录或管理员代设密码。OAuth 机器客户端授权、原生/设备客户端、动态注册、自定义业务 API 权限、第三方 API 令牌托管和跨应用协同退出也不在范围内，相应接口不对外开放。

用户名与显示名称分别设置。注册表单要求填写唯一用户名，长度为 3–30 个字符，仅含英文字母、数字、下划线或点；用户名以小写保存，登录不区分大小写。已有账号可以继续通过邮箱登录，并在个人资料中补设用户名。用户名可以修改，设置后不能清空。两种登录方式均要求邮箱已验证，邮箱登录只接受主邮箱。

**邮箱管理**独立页面统一管理一个主邮箱和多个辅助邮箱，所有地址在全部账号间保持唯一，不区分主辅。添加邮箱需要确认身份，并验证发送到该地址的验证码。已验证的辅助邮箱经身份确认后可设为主邮箱，原主邮箱保留为辅助邮箱。身份确认使用当前密码；无密码账号通过已绑定提供方再次认证，并完成已开启的 MFA。删除主邮箱前必须先切换。找回密码先输入用户名或主邮箱，再向该账号指定的已验证主邮箱或辅助邮箱发送验证码。辅助邮箱不能作为登录账号标识。

## 界面

在账号中心的「安全」页确认当前密码或通过已绑定身份再次认证，以绑定验证器。扫码或手动输入密钥，保存恢复码并验证动态码后开启 MFA。每个恢复码仅可使用一次，重置恢复码会使旧码立即失效。开启或关闭 MFA 会撤销其他会话及原有应用授权；找回密码不会关闭 MFA。丢失验证器时可使用恢复码登录，若两者都丢失，则无法通过密码恢复绕过 MFA。

管理员可在 `/zh-cn/admin/branding` 设置整站 Logo、品牌名、主题色与配色方案。Logo 与品牌名分别显示，Logo 和头像共用预览、裁剪、缩放、旋转及确认流程。Logo 使用固定正方形裁剪框并输出正方形图片，SVG 调整后仍保存为矢量图，静态 PNG、JPG、WebP 在浏览器中处理为 WebP 后上传。支持 9 种官方 Material 方案，默认使用调性点缀（Tonal Spot），统一生成浅色、深色两套各 49 个颜色角色。保存后同步更新站点品牌、浏览器元数据及账号邮件品牌，保持 issuer、用户 ID 和 OAuth client ID 稳定。详见[品牌设置架构](docs/architecture.md#branding)。

头像使用私有 R2 桶和 Better Auth 已有的 `user.image` 字段。在账号中心选择不超过 20 MiB 的静态 JPG、PNG 或 WebP 图片，在圆形裁剪框内直接拖动、缩放或旋转，支持鼠标、触摸与键盘操作。初始和最小缩放恰好铺满裁剪框，拖动范围限制在原图内。浏览器从原图生成与预览构图一致的 256 像素正方形，统一编码为 WebP 后上传，Worker 仅接受 WebP，检查尺寸和体积并移除元数据。资料页、顶部栏、用户管理与 OIDC `picture` 声明使用同一地址。修改头像会同步失效已有账号/管理缓存并通知其他标签页。详见[头像存储与生命周期](docs/architecture.md#avatars)及[部署前置条件](docs/deployment.zh-CN.md)。

账号中心、开发者中心和管理后台使用独立导航。个人资料、邮箱、安全、登录会话和已授权应用位于账号中心；用户可在「已授权应用」查看已同意的权限，撤销应用的同意记录与 OAuth 凭据，再次使用需要重新同意。已验证邮箱的账号在开发者中心创建和配置自己的应用；管理后台全局查看应用及开发者关联，链接到用户管理，并限制或恢复应用访问，应用详情只读。普通用户不能进入管理后台。

页面采用 Material Design 3 风格，在 React 19 中使用 **Material Web（`@material/web` 2.5.0）** Web Components。认证页面、个人中心和管理后台通过共享的 MD3 设计令牌统一颜色、排版、形状和交互样式。Roboto 和 Noto Sans SC 可变字体通过锁定版本的 Fontsource 包随应用打包，由本站提供，包含 Material 使用的 400/500/700 字重。WOFF2 字体按字符范围分片，采用 `font-display: optional`，并预加载常用的 Roboto 拉丁字集。字体未及时就绪时，当页保持系统回退字体，不再替换已经显示的文字。组件与字体均不依赖外部 CDN。

主题以 Cloudflare 橙色（`#F38020`）作为品牌强调色和主按钮底色，搭配深色文字；链接与焦点指示采用深橙，以确保在浅色背景上的对比度。

Logo 以橙色入口和登录箭头搭配 Loginflare 字标。[SVG Logo](public/assets/logo.svg) 的图形和文字均使用矢量路径，无内嵌图片或字体依赖。界面复用同一 Logo，字标颜色随主题调整；[站点图标](public/favicon.svg) 使用独立图形。

浅色与深色主题默认跟随系统。主题菜单可选择浅色、深色或跟随系统，选择保存在当前浏览器中，刷新后保留并在标签页之间同步，与账号语言偏好独立。初始主题在 React 加载前应用，Turnstile 同步使用当前主题。

桌面滚动条采用主题主色的细圆角滑块和透明轨道，触屏设备保留原生滚动行为。

Material Web 采用 Apache-2.0 许可证，目前上游处于[维护模式](https://github.com/material-components/material-web/discussions/5642)。Loginflare 锁定其版本，并保留第三方许可声明。

## 本地开发

需要 Node.js 24 LTS 和 `packageManager` 中约定的 pnpm 11.25.0。项目的 Cloudflare 工具已锁定在开发依赖中。按锁文件安装依赖并生成本地密钥：

```powershell
pnpm install --frozen-lockfile
pnpm setup:local
```

`setup:local` 会生成被忽略的 `.dev.vars`，包含随机认证密钥和官方 Turnstile 开发测试密钥；已有文件不会覆盖。`.dev.vars.example` 用于说明变量，其中的占位认证密钥会被拒绝。然后初始化本地数据库并启动应用：

```powershell
pnpm db:migrate
pnpm db:check
pnpm dev
```

访问 `http://localhost:5173`，与配置的认证 Origin 保持一致。首次访问根路径时自动匹配浏览器支持的语言。开发邮件绑定会在本地模拟发送，可通过模拟输出获取注册验证链接及邮箱管理、密码恢复验证码；不需要发送真实邮件或创建远程资源。生产不能使用 Turnstile 测试配置。

`pnpm dev` 会在每个 API GET 请求的正常处理时间之外，固定额外增加 1,000 毫秒延迟，便于在本地观察加载状态。`/api/health`、页面和静态资源，以及非 GET 请求不受影响。该中间件仅存在于 Vite 开发服务器；生产与 staging 构建、隔离的浏览器和容量自动化测试均不加人工延迟。

开发与运维命令共享 `.cloudflare/state`，本地 CLI 配置和运行时注册文件放在 `.cloudflare/tool-config`；两者都已忽略。资源操作优先使用 `cf`。当前锁定的 `cf` 开发/构建路径要求 Beta 版 Vite 插件，因此开发、构建、Worker 类型生成和部署使用稳定 Vite/Wrangler。该 `cf` 版本也尚未实现本地 D1 查询，故本地管理员提权使用 Wrangler，远程 D1 操作继续使用 `cf`。

### 首个管理员

先将预期的管理员注册为普通账号，并完成邮箱验证，再运行本地运维命令提升指定邮箱：

```powershell
pnpm admin:promote -- --email admin@example.com --local
```

命令要求账号已存在且邮箱已验证，可重复执行。提升后退出并重新登录。第一个注册用户不会自动成为管理员；网页后台不能分配角色或停用其他管理员。

## 规模与数据运维

用户、应用和活跃会话列表接口通过创建时间与 ID 的复合索引进行签名游标分页。账号会话与后台列表界面提供上一页、下一页和返回最新，仅显示本页条数；打开详情时在 URL 中保留游标和精确检索条件。列表不扫描精确总数，不使用 OFFSET。后台应用支持按完整客户端 ID 或名称匹配。开发者工作台以卡片展示自己的应用，空列表提供单一创建入口；其有界请求覆盖每人最多 20 个应用的限制。接口与验证范围参见[规模说明](docs/scaling.md)。

当前只实现 D1 数据库后端。“百万注册账号”描述存储规模，不代表百万并发，也不是固定吞吐保证。公开部署前应结合实际流量、数据库大小、邮件量和 Cloudflare 套餐限制进行验证。Hyperdrive 或外部 SQL 数据库属于未来独立接入工作，当前不能切换使用。

迁移会把原生日期统一为 ISO UTC 文本，准备有索引的回调 Origin 元数据，并按已提交迁移检查最终结构。更新已有数据库前先备份，并将 issuer、认证密钥与数据库一起保留。过期数据和旧头像文件由有界定时任务清理，共用 Worker、D1 和头像存储桶。

## 验证

`pnpm check` 执行类型检查、Worker 集成测试、运维命令测试和生产构建；浏览器流程另用 `pnpm test:e2e` 验证。[CI 工作流](.github/workflows/ci.yml) 会在 PR 和推送到 `main` 时执行这两组检查，以及使用 10、10,000 个生成用户和三秒负载窗口的隔离规模检查。测试使用本地 D1、模拟邮件和 Turnstile 测试密钥，浏览器报告保留七天。百万用户基准仍单独手动运行。

```powershell
pnpm typecheck
pnpm test
pnpm test:ops
pnpm test:e2e
pnpm test:scale
pnpm build
```

浏览器测试会先构建应用，再于 `http://localhost:5174` 启动独立 Miniflare，数据和捕获邮件放在 `work/e2e/<run-id>`。测试夹具模拟 Turnstile，拒绝外部浏览器/API 请求并关闭 API 自动重定向；Worker 仅允许向自身发起本地 JWKS 请求。测试不复用日常开发数据库或服务。Windows 默认使用已安装的 Chrome，可用 `PLAYWRIGHT_CHANNEL` 指定其他浏览器渠道；其他平台默认使用 Playwright Chromium。安装依赖和浏览器仍需要正常下载。

集成与浏览器测试使用本地数据、模拟邮件和 Turnstile 测试响应，不应连接远程账号或数据库。`pnpm test:scale` 在独立目录使用生成数据验证规模，不创建付费 Cloudflare 资源，不发送真实邮件；参数与报告范围参见[规模说明](docs/scaling.md)。新机器设置 Playwright 时安装 Chromium：

```powershell
pnpm exec playwright install chromium
```

## 账号行为

- 验证邮箱后才能登录。
- 修改密码需要当前密码，成功后撤销其他会话。
- 重置密码撤销全部会话，需要重新登录。
- 停用账号撤销已有会话并阻止新登录；恢复账号不会恢复旧会话。
- 会话通过 D1 校验，不使用缓存的 Cookie 用户快照。
- 角色、邮箱验证状态和停用状态仅由服务端设置。
- 受保护响应不缓存；日志不应包含密码、会话令牌或完整的验证/重置链接。

密码长度为 8–128，注册邮箱验证令牌有效期为一小时，会话有效期为七天并按 Better Auth 默认规则续期，同时关闭 Cookie 会话缓存。邮箱管理与密码恢复验证码有效期为十分钟，最多尝试五次；恢复验证通过后，使用十分钟有效的令牌交给 Better Auth 原生流程重置密码。每个账号最多管理十个邮箱；未验证辅助邮箱占用超过一天后，再次添加该地址时可回收。

## 接入其他应用

使用已验证邮箱的账号登录，切换到**开发者中心 → 我的应用**，即可创建服务端 Web 或 SPA 客户端。每位开发者最多拥有 20 个应用，只能管理自己的应用。**管理后台 → 应用**用于全局只读查看和访问管控，包括原有实例应用，不提供创建、修改配置或轮换密钥；开发者不能解除管理员的限制。

先在 Loginflare 登记外部应用的精确登录、退出回调，再到该应用的 OIDC 配置中填写生成的客户端 ID、issuer，以及服务端客户端的一次性密钥。服务端应用使用 `client_secret_basic`；浏览器 SPA 使用 `none`，不获取客户端密钥。两者均要求授权码 + PKCE S256，并在首次使用时取得用户同意。发现文档位于 `${AUTH_URL}/api/auth/.well-known/openid-configuration`。

[接入说明](docs/oauth.zh-CN.md)包含回调配置、令牌有效期、安全事件撤销策略，以及标准 `openid-client` / `oidc-client-ts` 示例。示例使用本地 HTTPS 子域和本地生成的证书，不修改系统证书信任，也不创建远程资源。

普通中心退出保留上游 `offline_access` 刷新授权语义。应用自行管理本地会话，退出 Loginflare 不代表所有应用都退出。密码恢复、停用账号等安全操作另有凭据失效规则，详见接入说明。

## 数据缓存与页面状态

账号中心与管理后台使用统一的 TanStack Query 内存缓存。普通读取保持 60 秒新鲜期，身份与会话视图为 15 秒；过期数据在后台更新时继续显示。写操作同步失效相关视图，并向其他标签页通知失效事件。非活跃私人查询、普通草稿和滚动位置均有数量限制。站内切页保留适合恢复的状态，F5 重新获取身份和当前页数据。密码、验证码和一次性客户端密钥不进入通用缓存或持久化存储。导航、错误与安全边界详见[浏览器数据合同](docs/architecture.md#browser-data-and-navigation)。

## 语言与网址

程序、翻译资源、账号偏好及 HTML `lang` 使用 `en-US` / `zh-CN`，网址语言段使用 `en-us` / `zh-cn`。显式页面网址决定当前语言，语言切换保留当前页面和查询参数，不改写大小写敏感的令牌。

根入口依次采用浏览器中已保存的偏好、已登录账号的偏好、浏览器语言列表中首个受支持的语言，最后回退 `en-US`。英语变体使用 `en-US`，中文变体使用当前提供的简体中文 `zh-CN`。根路径与语言入口均保留查询参数和片段，已登录时进入账号中心，未登录时进入登录页。React 渲染前的初始翻译与 HTML `lang` 使用同一套语言判定。未知或大小写不规范的语言段返回 404。API 保持 `/api/*`，不加语言前缀。事务邮件采用账号语言偏好，完成验证或重置后返回对应语言页面。

## 部署

请查看[部署说明](docs/deployment.zh-CN.md)，配置测试与生产环境的数据隔离、密钥、域名和发信能力，再应用迁移、初始化管理员。

Cloudflare Email Sending 当前为 Beta，向任意用户发送事务邮件需要 Workers Paid。生产需要已验证发信域名和正式 Turnstile 配置。安全配置缺失时应用明确报错，不会跳过邮箱验证或防机器人校验。

本地安装、测试和构建不涉及远程资源创建、真实邮件发送或部署。执行这些操作时，应先确认目标环境并取得相应授权。
