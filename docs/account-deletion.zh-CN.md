# 账号注销


[English](account-deletion.md)

已验证且有效的普通用户可在**账号中心 → 安全 → 注销账号**发起操作。密码账号须确认当前密码，已启用 MFA 时还须输入当前 TOTP；无密码账号通过已绑定提供方重新认证，完成已开启的 MFA 后取得用户、会话和 `account/delete` 用途绑定的短期证明。

确认页列出名下应用名称和 client ID，并要求明确勾选删除声明。删除应用会删除所有用户对它的授权，其他人的账号、其他应用和实例级机器身份保持独立。管理员不能自助注销，也不增加管理员、运营或机器代删接口，不提供应用转移。若历史实例管理应用的原生 `userId` 引用该普通账号，须先由运营者处理依赖，不会自动删除这些应用。

## API

接口使用当前浏览器选择的账号及会话，只允许同源操作；client ID 和机器令牌不能代替用户身份。

- `GET /api/account/deletion-preview` 返回 `{ preview, applications: [{ clientId, name }], expiresIn: 600 }`，签名预览绑定用户、当前会话和应用清单，不包含凭据。
- `POST /api/account/delete` 接受 `{ preview, password?, code? }`，要求 JSON 和精确 Origin。无密码账号使用之前签发的 HttpOnly 证明 Cookie。拒绝额外字段，包括指定目标用户。成功返回 `202 { operationId, status: "pending" }`。

无会话或账号不符合要求返回 401/403。过期或属于其他会话的预览返回 400；最终写入检测到应用、凭据或 MFA 状态变化时返回 409，要求重新确认。缺少 TOTP 返回 `ACCOUNT_DELETION_MFA_REQUIRED`，错误代码使用原生 MFA 错误。POST 每个账号每分钟最多尝试五次，429 提供 `Retry-After`。响应不明时不会自动重复写入。

## 冻结与清理

接受请求时，D1 事务重新检查会话、密码哈希或已消费证明、MFA 配置、普通用户身份与精确应用清单，然后创建唯一持久化任务、停用有效的自有应用、冻结账号并写入接受审计。原本停用或受限的应用保持停用。注销标记阻止恢复账号、修改资料或凭据及再次签发凭据；在线令牌检查立即拒绝访问。离线验证的 JWT 和业务应用自己的会话仍依照其过期与复核策略。

现有五分钟 Cron 在维护预算内每次最多执行四批注销工作，为普通过期清理保留容量，每次变更选择最多 100 条记录。任务使用一分钟租约和持久化阶段，中断后由后续调用继续。先清理 Access Token，再清理 Refresh Token；先清理授权码和授权账本，再清理同意记录；先处理子表，再删除应用和账号。阶段编号已持久化，后续版本不得在没有迁移的情况下重排。未完成任务不过期；完成回执与审计保留 90 天。失败沿用 `database_maintenance_failed`，运营者可用操作或用户 ID 定位任务和审计。

原生邮箱验证令牌只标识邮箱。系统会拒绝早于当前账号创建的旧验证链接，并至少保留地址预留两秒，避免删除后立即重新注册落在相同 JWT 时间秒内。这不是清理完成时间承诺。

头像元数据解除关联后交给现有 R2 清理器；对象删除失败时保留重试信息。对象移除后，公开头像缓存仍可能显示最多五分钟。安全审计沿用 90 天保留策略，不记录密码、证明令牌、TOTP 或应用密钥。中英文 `/account-deleted` 页面只显示操作说明，不查询或暴露任务、账号资料。

使用此版本前应用 `0025_account_deletion.sql`。迁移追加任务、守卫和索引，保持普通封禁行为，同时避免注销阶段触发全量授权级联撤销。既有线上迁移仍需摘要审核，本次不会批准或执行远程迁移、部署。
